# PRD v1.1 — 宠物诊所口碑推荐小程序

## 一、产品定位

### 1.1 产品一句话

提供用户**快速找到附近"口碑好 / 性价比高"宠物诊所**的轻量工具。

---

### 1.2 核心价值

- 用户：避免踩坑，降低决策成本
- 诊所：获得真实用户线索
- 平台：构建真实标签数据闭环

---

### 1.3 产品原则

- 极简（不做复杂功能）
- 去商业化排序（信任优先）
- 标签驱动（非评分体系）

---

## 二、核心用户路径

```
进入小程序 → 自动定位 → 展示附近诊所列表 → 标签筛选（口碑/性价比）→ 查看诊所详情 → 点击预约（电话/微信）→ 就诊后打标签
```

---

## 三、功能结构

### 3.1 首页（核心页）

#### 功能目标
用户进入后 **3秒内看到可选诊所**

#### 页面结构

**① 顶部区域**
- 当前城市（自动定位，可手动切换）
- 搜索框：**V1不做**，预留位置

**② 距离筛选**
- 默认：**3km**
- 可选：3km / 10km / 20km
- 交互：底部弹出选择器

**③ Tab切换（核心）**
- 【口碑优先】（默认）
- 【性价比优先】

**④ 标签筛选（横滑）**

基于四层标签体系，首页仅展示 **L1 用户决策层标签**：

**信任类标签（Trust）：**
- 不乱开药

- 解释清楚病情
- 没有隐性收费

**性价比类标签（Value）：**
- 价格透明
- 基础诊疗便宜

**服务体验类标签（Experience）：**

> 💡 **设计说明**：标签体系采用四层结构（详见"标签体系设计"章节），首页仅展示L1层，其他层级用于排序和推荐算法。

每个卡片包含：

### 3.2 排序逻辑（防刷 + 真实权重）

> **核心问题**：怎么让真实好诊所排前面，而不是会运营的诊所排前面

---

#### 算法底线（必须满足）

排序必须满足：
- ✔ 不能被单一变量操控
- ✔ 不能被付费影响
- ✔ 要抗小样本波动
- ✔ 要强调"长期一致性"

---

#### 综合排序公式（V2升级版）

```
综合分数 = TrustScore × 0.45 
         + ValueScore × 0.25 
         + ExperienceScore × 0.15 
         + SocialProof × 0.15 
         - RiskPenalty
```

**权重调整说明：**
- Trust从0.5降至0.45（防止单一维度操控）
- Social从0.1提升至0.15（强调长期一致性）
- 总权重100%，风险惩罚额外扣除

---

#### 各维度详细计算方式

##### 🟢 TrustScore（信任分）- 权重45%

**核心指标：**
- 不乱开药比例
- 不过度检查比例
- 满意率

**计算公式：**
```
TrustScore = (正向标签数 - 负向标签数) / 总标签数 × 用户去重权重 × 100
```

**关键机制：用户去重权重（防刷核心）**

| 用户行为 | 权重 | 说明 |
|---------|------|------|
| 第1次评价 | 1.0 | 完整权重 |
| 第2次评价 | 0.3 | 大幅降权 |
| 第3次及以上 | 0.1 | 几乎无效 |

**示例：**
```
诊所A：10个用户，每人1次评价，8个正向
TrustScore = (8 - 2) / 10 × 1.0 × 100 = 60分

诊所B：3个用户，每人多次评价，20个正向
TrustScore = (20 - 0) / 20 × 0.3 × 100 = 30分

→ 诊所A排名更高（真实用户更多）
```

---

##### 🟡 ValueScore（性价比分）- 权重25%

**核心指标：**
- 价格透明
- 基础治疗好评
- 不强推高价项目

**计算公式：**
```
ValueScore = 性价比标签加权数 / 总标签数 × 用户独立性系数 × 100
```

**防刷关键：必须来自"不同用户 + 不同时间"**

**用户独立性系数：**
```
独立性系数 = MIN(1.0, 独立用户数 / 5)
```

**说明：**
- 至少需要5个独立用户，系数才能达到1.0
- 少于5个用户，系数按比例降低

**示例：**
```
诊所A：10个性价比标签，来自8个独立用户
独立性系数 = MIN(1.0, 8/5) = 1.0
ValueScore = 10 / 15 × 1.0 × 100 = 66.7分

诊所B：20个性价比标签，来自3个独立用户
独立性系数 = MIN(1.0, 3/5) = 0.6
ValueScore = 20 / 25 × 0.6 × 100 = 48分
```

---

##### 🔵 ExperienceScore（体验分）- 权重15%

**核心指标：**
- 医生态度
- 等待时间
- 环境

**计算公式：**
```
ExperienceScore = 体验标签加权数 / 总标签数 × 100
```

**权重最低原因：**
- 防止主观因素过度影响
- 体验类标签容易被操控
- 信任和性价比更重要

---

##### 🟣 SocialProof（社交证明）- 权重15%

**不是"点赞数"，而是：**
- 被推荐次数
- 回头客比例
- 多用户重复出现

**计算公式：**
```
SocialProof = (回头客比例 × 0.5 + 推荐次数系数 × 0.3 + 用户活跃度 × 0.2) × 100
```

**各指标计算：**

**回头客比例：**
```
回头客比例 = 复购用户数 / 总用户数
```

**推荐次数系数：**
```
推荐次数系数 = MIN(1.0, 推荐次数 / 20)
```

**用户活跃度：**
```
用户活跃度 = 近30天活跃用户数 / 总用户数
```

**防刷核心：同一来源链权重衰减**
```
如果用户A推荐了B、C、D...
第1个推荐权重 = 1.0
第2个推荐权重 = 0.5
第3个及以上 = 0.2
```

---

##### 🔴 RiskPenalty（风险惩罚）- 核心护城河

**风险信号（触发条件）：**
- 负面标签 ≥ 2个独立用户
- 同类投诉集中（≥3次）
- 价格争议记录

**计算公式：**
```
RiskPenalty = Σ(负面标签权重 × 时间衰减因子 × 用户独立性权重)
```

**时间衰减因子：**
| 时间范围 | 衰减因子 | 说明 |
|---------|---------|------|
| 30天内 | 1.0 | 完整惩罚 |
| 31-60天 | 0.7 | 开始衰减 |
| 61-90天 | 0.4 | 大幅衰减 |
| 90天以上 | 0.2 | 历史记录 |

**用户独立性权重：**
```
独立性权重 = MIN(1.0, 独立投诉用户数 / 3)
```

**惩罚力度：**
```
每个风险标签基础扣分 = 15分
实际扣分 = 15 × 时间衰减因子 × 独立性权重
```

**示例：**
```
诊所A：2个"乱收费"标签，来自2个独立用户，30天内
RiskPenalty = 15 × 1.0 × (2/3) = 10分

诊所B：5个"乱收费"标签，来自5个独立用户，30天内
RiskPenalty = 15 × 1.0 × 1.0 = 15分
```

**重点：**
- ❗风险比正向权重更"重"
- 负面标签的影响力 > 正面标签
- 多个独立用户投诉 = 严重问题

---

#### 防刷机制（三层防护）

##### 1️⃣ 用户去重（第一层）

**同一用户对同一诊所：**
```
第1次评价权重 = 100%
第2次评价权重 = 30%
第3次评价权重 = 10%
```

**实现方式：**
```sql
SELECT user_id, COUNT(*) as eval_count
FROM user_tag_log
WHERE clinic_id = ?
GROUP BY user_id
```

---

##### 2️⃣ 时间衰减（第二层）

**标签时效性：**
| 时间范围 | 权重 | 说明 |
|---------|------|------|
| 最近30天 | 1.0 | 完整权重 |
| 31-60天 | 0.7 | 开始衰减 |
| 61-90天 | 0.4 | 大幅衰减 |
| 90天以上 | 0.2 | 历史参考 |

**目的：**
- 反映诊所当前状态
- 防止"历史刷分"长期影响
- 鼓励持续好评

---

##### 3️⃣ 交叉验证（第三层）

**标签生效条件：**
```
只有当 ≥2个独立用户 给出相同标签
标签才进入"有效状态"
```

**标签状态：**
| 状态 | 条件 | 是否参与排序 |
|-----|------|------------|
| 待验证 | <2人 | 否 |
| 已验证 | ≥2人 | 是 |
| 稳定 | ≥10人 + 30天 | 是（权重1.2） |

---

#### 排序最终逻辑（简单版本）

```
1. 先过滤风险过高诊所（RiskPenalty > 20分）
   ↓
2. 计算 TrustScore（45%）
   ↓
3. 计算 ValueScore（25%）
   ↓
4. 计算 ExperienceScore（15%）
   ↓
5. 计算 SocialProof（15%）
   ↓
6. 扣除 RiskPenalty
   ↓
7. 得到最终分数
   ↓
8. 按分数降序排列
```

---

#### 口碑优先排序（调整权重）

```
排序分数 = TrustScore × 0.55 
         + ValueScore × 0.20 
         + ExperienceScore × 0.15 
         + SocialProof × 0.10 
         - RiskPenalty
```

**说明：**
- Trust权重提升至55%
- Value权重降至20%
- 更强调信任度

---

#### 性价比优先排序（调整权重）

```
排序分数 = ValueScore × 0.40 
         + TrustScore × 0.35 
         + ExperienceScore × 0.15 
         + SocialProof × 0.10 
         - RiskPenalty
```

**说明：**
- Value权重提升至40%
- Trust权重降至35%
- 但Trust仍然重要（防止纯低价诊所）

---

#### ❗禁止参与排序的因素

- 付费情况
- 预约量（可能被刷）
- 广告投放
- 诊所规模
- 单一用户的多次评价

---

#### 小样本保护机制

**问题：**
- 新诊所标签数少，分数波动大
- 可能因为1-2个差评排名暴跌

**解决方案：置信度系数**

```
置信度系数 = MIN(1.0, 总标签数 / 20)

最终分数 = 计算分数 × 置信度系数 + 基准分数 × (1 - 置信度系数)
```

**基准分数：**
- 城市平均分：60分

**示例：**
```
新诊所A：5个标签，计算分数80分
置信度系数 = 5/20 = 0.25
最终分数 = 80 × 0.25 + 60 × 0.75 = 65分

成熟诊所B：50个标签，计算分数80分
置信度系数 = 1.0
最终分数 = 80 × 1.0 + 60 × 0 = 80分
```

**目的：**
- 新诊所向平均分回归
- 需要积累足够标签才能排名靠前
- 防止刷分快速上位

---

#### 核心原则总结

> **把"谁会运营"变成"谁真的被反复验证"**

**不是让会刷的诊所排前面，而是：**
- 让真实用户多的诊所排前面（用户去重）
- 让长期稳定的诊所排前面（时间衰减）
- 让多人验证的诊所排前面（交叉验证）
- 让有风险的诊所排后面（风险惩罚）

### 3.4 预约模块（轻实现）

#### 行为逻辑

用户点击预约时：

### 3.5 标签反馈机制（核心闭环）

> **设计原则**：把"随意评论"变成"结构化判断选择"，降低选择成本 + 防刷

---

#### 标签交互原则（必须遵守）

**❌ 不要做：**
- 自由输入长评论
- 多层筛选
- 复杂UI
- 类点评系统

**✔ 必须做：**
- 点选
- 限制数量
- 场景化问题引导
- 3秒内完成选择

---

#### 触发时机

**方式1：主动触发**
- 用户在详情页底部看到"我已就诊，打标签"按钮

**方式2：被动提醒**
- 用户点击预约后24小时，推送服务通知
- 文案："您在【XX诊所】的就诊体验如何？"

---

#### UI结构（三层设计）

##### 🧠 第一层：快速情绪判断（必选1个）

**标题**："这次就诊体验怎么样？"

**交互**：用按钮，不用标签

```
┌─────────────────────────────────┐
│  👍 很满意   😐 一般   👎 不满意  │
└─────────────────────────────────┘
```

**目的**：快速分流，不同情绪进入不同标签池

---

##### 🧠 第二层：原因选择（最多选3个）

**根据第一层选择，展示不同标签池：**

**如果选择 👍 很满意：**
- 医生很专业
- 价格合理
- 解释清楚
- 不乱推荐检查
- 对宠物很耐心
- 环境干净

**如果选择 😐 一般：**
- 价格略高
- 等待时间长
- 沟通一般
- 检查项目多
- 环境一般

**如果选择 👎 不满意：**
- 乱收费
- 过度检查
- 不专业
- 体验差
- 态度不好
- 强推高价项目

**核心设计点：**
- ❗不同情绪 → 不同标签池（这是防刷关键）
- 最多选3个
- 必须至少选1个

---

##### 🧠 第三层：补充标签（可选，最多选2个）

**轻标签（不影响排序，仅供参考）：**
- 猫更友好
- 狗更友好
- 急诊不错
- 有停车位
- 交通方便
- 可以洗澡

**说明**：
- 这一层可跳过
- 最多选2个
- 权重较低（0.3）

---

#### 标签映射到四层体系

**情绪判断 → 标签层级映射：**

| 用户选择 | 映射到标签层 | 权重 |
|---------|------------|------|
| 👍 很满意 + 医生很专业 | L1-Trust: 不乱开药 | 1.0 |
| 👍 很满意 + 价格合理 | L1-Value: 价格透明 | 1.0 |
| 👍 很满意 + 对宠物耐心 | L1-Experience: 对宠物耐心 | 1.0 |
| 😐 一般 + 价格略高 | L1-Value: 基础诊疗便宜（负向） | 0.5 |
| 👎 不满意 + 乱收费 | L3-Risk: 有价格争议记录 | 1.0 |
| 👎 不满意 + 过度检查 | L3-Risk: 过度推荐手术嫌疑 | 1.0 |

---

#### UI防刷设计（很重要）

##### 1️⃣ 限制频率
- 同一用户同一诊所：**只能一次评价**
- 数据库唯一索引强制约束

##### 2️⃣ 不允许"全选"
- 第一层：必选1个
- 第二层：最多3个，至少1个
- 第三层：最多2个，可跳过

##### 3️⃣ 行为触发而不是主动评论
- 只能在"就诊后流程"出现
- 未预约用户不能直接打标签（或权重极低0.3）

##### 4️⃣ 时间限制
- 预约后7天内有效
- 超过7天不再提醒

##### 5️⃣ 异常检测
- 同一设备短时间内多次评价 → 降权
- 评价模式高度相似 → 人工审核

---

#### 打标签流程（完整）

```
用户点击"已就诊" 
    ↓
弹出标签选择页
    ↓
第一层：选择情绪（必选1）
    ↓
第二层：选择原因（1-3个）
    ↓
第三层：补充标签（0-2个，可跳过）
    ↓
提交
    ↓
映射到四层标签体系
    ↓
记录到数据库（user_tag_log）
    ↓
异步更新统计（clinic_tag_stat）
    ↓
触发分数重新计算
```

---

#### 限制规则（完整版）

| 规则 | 说明 | 权重 |
|-----|------|------|
| 一次评价 | 一个用户对一个诊所只能打一次标签 | - |
| 预约后评价 | 预约后打标签 | 1.0 |
| 普通评价 | 未预约但已就诊（需验证） | 0.5 |
| 新用户评价 | 注册7天内 | 0.3 |
| 时间限制 | 预约后7天内 | 1.0 |
| 超时评价 | 预约后7-30天 | 0.7 |
| 过期评价 | 预约后30天以上 | 不允许 |

---

#### 目的总结

> **把"评论系统"变成"结构化反馈系统"**

**不是让用户表达更多，而是：**
- 让用户在3秒内做出可信选择
- 通过情绪分流防止刷标签

- 通过行为触发保证真实性

## 四、标签体系设计（核心壁垒）

### 4.0 标签体系 v2 — 四层结构模型

> **核心理念**：把"宠物诊所好不好"从主观评价，变成结构化信用模型

---

#### 设计目标

标签体系必须同时满足：

1. **可理解**（用户视角）：用户能快速判断好/不好/贵不贵
2. **可计算**（系统视角）：能参与排序，而不是装饰
3. **抗污染**（防刷）：不允许自由发散
4. **可扩展**（未来能力）：能支撑"专业能力地图"

---

#### 四层标签结构

##### 🧩 L1：用户决策层（User Decision Layer）

**作用**：首页展示，直接影响用户决策

**① 信任类（Trust）** - 代表"不会坑你"
- 不乱开药
- 不过度检查
- 解释清楚病情
- 没有隐性收费

**② 性价比类（Value）** - 代表"值不值"
- 价格透明
- 基础诊疗便宜
- 不强推高价项目
- 检查合理收费

**③ 服务体验类（Experience）** - 代表"体验好不好"
- 医生态度好
- 对宠物耐心
- 环境干净
- 响应快

---

##### 🧠 L2：医疗能力层（Medical Capability Layer）

**作用**：不直接展示，用于排序和推荐算法（未来壁垒）

**④ 专科能力（Capability）**
- 猫专科
- 狗外科
- 皮肤病专长
- 骨科能力
- 急诊能力
- 传染病处理

**⑤ 设备能力（Infrastructure）**
- 有DR/X光
- 有B超
- 可做手术
- 可住院
- 有化验室

> 💡 **V1暂不开放**，V2版本启用，用于精准推荐（如："附近哪家能做骨科手术"）

---

##### 🚨 L3：风险标签层（Risk Signal Layer）

**作用**：核心护城河，用于降权和风控（行业没人敢做）

**⑥ 风险信号（Negative Trust）**
- 有价格争议记录
- 有过医疗纠纷
- 过度推荐手术嫌疑
- 用户投诉较多
- 多次更换医生

**展示规则：**
- ❗不在首页显眼位置展示
- 仅在详情页底部灰色区域提示
- 主要用于：降权、风控、排序修正

**触发机制：**
- 用户主动标记（需审核）
- 系统行为推断（如：退款率高）
- 多人投诉（≥3人）

---

##### 📢 L4：传播标签层（Social Proof Layer）

**作用**：轻权重，用于冷启动和增长

**⑦ 社交传播类**
- 被推荐次数高
- 回头客多
- 熟人推荐率高
- 本地口碑好

**生成方式：**
- 系统行为推断（如：同一用户多次预约 → "回头客多"）
- 用户邀请数据统计
- 社交分享次数

---

#### 标签生成机制（决定能否活下来）

##### 1. 标签不能自由输入（关键原则）

**✅ 允许：**
- 用户从预设标签中选择
- 系统根据行为推导

**❌ 禁止：**
- 自由文本评论
- AI从评论中抽取标签（V1不做）

##### 2. 标签来源三条路径

**① 用户行为（主来源）**
- 就诊后选择标签（最多3个）
- 权重：预约后打标签 = 1.0，普通打标签 = 0.5

**② 多人共识（加权）**
- ≥3人选择同一标签 → 标签生效
- <3人 → 标签存在但不展示

**③ 行为推断（系统）**
- 频繁复购 → "回头客多"
- 价格集中在低区间 → "性价比高"
- 退款率高 → 触发风险标签

---

#### 标签权重体系（用于排序）

##### 权重模型

```
综合分数 = Trust × 0.5 
         + Value × 0.3 
         + Experience × 0.2 
         - RiskPenalty
         + SocialProof × 0.1
```

**权重说明：**
- **Trust（信任）= 50%**：最高权重，宠物医疗是强信任行业
- **Value（性价比）= 30%**：次要但重要
- **Experience（体验）= 20%**：加分项
- **RiskPenalty（风险惩罚）**：每个风险标签 -10分
- **SocialProof（社交证明）= 10%**：传播加成

---

#### 标签生命周期（防污染核心）

每个标签有生命周期状态：

| 状态 | 条件 | 权重 | 是否展示 |
|-----|------|------|---------|
| **新标签** | <3人标记 | 0.3 | 否 |
| **验证标签** | ≥3人标记 | 1.0 | 是 |
| **稳定标签** | ≥10人 + 30天稳定 | 1.2 | 是（加粗） |
| **失效标签** | 90天无新增 | 0.5 | 是（灰色） |

**目的**：防止"短期刷标签影响长期排序"

---

#### 系统演化路径（如何变强）

**Phase 1（V1.0 - 现在）**
- 人工录入 + 用户标签
- 基础排序（L1层）
- 简单防刷

**Phase 2（V1.5 - 3个月后）**
- 行为推断标签（L4层）
- 风险模型启用（L3层）
- 标签生命周期管理

**Phase 3（V2.0 - 6个月后）**
- 医疗能力层启用（L2层）
- 城市级医疗画像
- 诊所真实能力图谱
- 精准推荐（"附近哪家能做猫绝育"）

**Phase 4（V3.0 - 壁垒形成）**
- 成为"宠物医疗的信用地图"
- 标签的生成权 + 解释权 + 权重体系
- 行业标准制定者

---

#### 这个体系的真正护城河

不是标签本身，而是：

1. **标签的生成权**：什么算好诊所，我们定义
2. **标签的解释权**：标签背后的权重模型
3. **标签的演化能力**：从用户决策到行业地图

> 💡 **一句话总结**：把"宠物诊所好不好"从主观评价，变成结构化信用模型。

## 八、风控机制

### 7.1 防刷规则

- 单用户单诊所只能打一次标签
- 新注册用户（7天内）权重降低为0.3
- 单用户每天最多打标签5次
- 单IP每小时最多操作20次

### 8.2 异常检测

- 短时间内大量相同标签 → 人工审核
- 单诊所标签数突增 → 触发预警
- 同一设备多账号 → 降权处理
- 风险标签触发 → 自动降权（-10分/个）

### 8.3 标签污染防护

**多人共识机制：**
- 标签需≥3人标记才生效
- 新标签不参与排序（权重0.3）
- 稳定标签权重提升（1.2倍）

**时间衰减机制：**
- 90天无新增的标签自动降权
- 防止"历史刷标签"长期影响排序

**用户信用体系：**
- 新用户（7天内）权重0.3
- 正常用户权重1.0
- 高质量用户（多次准确标记）权重1.2
