# 诊所数据模型 V2 实施任务清单

> 来源：基于“诊所数据模型 V2”讨论结果拆解
> 目标：把“基础档案 + 能力档案 + 口碑证据”模型转成可排期、可开发、可验收的任务列表

---

## 1. 使用方式

建议把这份清单直接同步到项目管理工具中，字段建议如下：

- 任务编号
- 任务名称
- 优先级：P0 / P1 / P2
- 状态：Todo / Doing / Review / Done / Blocked
- 负责人
- 预计工时
- 依赖任务
- 交付物
- 验收标准

---

## 2. 本次范围

本次 V2 只处理以下内容：

- 诊所基础档案补强
- 诊所能力字典与能力关联模型
- 推荐/补充链路支持能力信息提交
- 后台审核支持能力信息入库
- 诊所详情页展示结构升级
- 搜索/筛选支持部分能力维度

本次不纳入范围：

- 重新设计评分算法
- 把能力标签直接纳入口碑总分
- 复杂的多级审核工作流
- 大规模历史数据自动清洗

---

## 3. 总体里程碑

### M1：数据模型定稿并可迁移

目标：

- 数据表结构定稿
- migration 可落地
- 种子能力字典可初始化

### M2：后台录入与审核可用

目标：

- 用户可提交能力补充信息
- 审核员可审核并写入诊所能力档案
- 诊所详情接口可返回能力信息

### M3：前台展示与筛选可用

目标：

- 详情页能展示“医疗能力”模块
- 列表页和搜索页能按高价值能力筛选
- 基础联调和测试通过

## 5. 后端接口任务

- [ ] `V2-07` 补齐能力定义相关 DTO / 枚举 / 校验器

  - 预计工时：0.5 天

  - 优先级：P0

  - 交付物：`clinic-submissions` DTO、service、测试
  - 验收标准：提交推荐时能力信息可成功落库到 `clinic_submission`

- [ ] `V2-09` 扩展推荐审核逻辑，支持将能力信息写入正式档案

  - 依赖：`V2-04`、`V2-05`、`V2-08`
  - 范围：
    - 审核通过新诊所时写入能力记录
    - 审核补充/纠错时更新能力记录
    - 合并时避免重复能力项
  - 验收标准：审核通过后，正式诊所档案与能力档案同步更新

- [ ] `V2-10` 扩展诊所详情接口返回 `capabilities`

    - `services`
    - `specialties`
    - `equipment`
    - `facilities`
    - `speciesSupported`
  - 验收标准：详情接口可按分组返回能力信息，并保留原有 `tags` 结构

- [ ] `V2-11` 扩展诊所搜索/列表接口支持能力筛选
  - 优先级：P1
  - 预计工时：1 天
  - 依赖：`V2-04`、`V2-10`
  - 首批筛选建议：
    - `specialty`
    - `equipment`
    - `facility`
  - 验收标准：可查询“有B超”“可住院”“猫专科”等高价值组合条件

- [ ] `V2-12` 扩展诊所详情缓存与失效策略
  - 优先级：P1
  - 预计工时：0.5 天
  - 依赖：`V2-10`
  - 验收标准：能力信息变更后，详情缓存不会长时间脏读

## 9. 推荐实施顺序

1. 先做 `V2-01` 到 `V2-06`，把模型、表结构、种子数据定住。
2. 再做 `V2-07` 到 `V2-12`，把后端提交、审核、详情、筛选接口补齐。
3. 再做 `V2-13` 到 `V2-16`，把后台审核和管理能力补上。
4. 再做 `V2-17` 到 `V2-20`，把推荐页、详情页、筛选 UI 接起来。
5. 最后做 `V2-21` 到 `V2-24`，补测试、文档和 staging 数据。
