# 真机测试清单

## 目标

这份文档是给“明天起床直接开测”用的，不讲大而全，只保留真机联调前最需要确认的步骤。

## 1. 今晚不用再想的结论

- 仓库代码已经提交并推到 GitHub
- 前端 lint 已通过
- 后端 build 已通过
- 备份、回滚、测试账号和提审说明都已经落到仓库文档

## 2. 明天开测前 10 分钟准备

### 2.1 后端

在根目录先确认依赖服务：

```powershell
podman compose up -d postgres redis
```

或：

```powershell
docker compose up -d postgres redis
```

再启动后端：

```powershell
cd backend
npm run migration:run
npm run start:dev
```

### 2.2 健康检查

确认后端正常：

```text
http://localhost:3000/api/v1/health
http://localhost:3000/api-docs
```

### 2.3 微信开发者工具

打开目录：

```text
D:\codeSpace\petMed\frontend
```

重点确认：

1. `frontend/project.config.json` 已配置为当前小程序的正式 `appid`
2. 如果你本地有旧项目缓存或重新导入，请确认没有被覆盖回 `touristappid`
3. 如果要走 `trial` / `release` 域名，请同步确认微信后台合法请求域名

如果本地后端不是默认 `3000`，先复制并修改本地配置：

```powershell
Copy-Item frontend/config/local.example.js frontend/config/local.js
```

## 3. 当前前端环境约定

前端 API 配置文件：

- [frontend/config/index.js](/D:/codeSpace/petMed/frontend/config/index.js:1)

默认行为：

- `develop` -> `http://localhost:3000/api/v1`，可用 `frontend/config/local.js` 覆盖
- `trial` -> `https://api-staging.petmed.example.com/api/v1`
- `release` -> `https://api.petmed.example.com/api/v1`

如果明天先做本机真机联调，优先测 `develop`。

## 3.1 真机联调前最后确认

如果你今天就要开始联调，先确认这 4 件事：

1. 微信开发者工具里打开的是 `D:\codeSpace\petMed\frontend`
2. 当前小程序 `appid` 与要联调的账号一致
3. 后端 `http://localhost:3000/api/v1/health` 正常，若本地端口上浮则以 `frontend/config/local.js` 为准
4. `wx.login()` 后能拿到 token 并成功请求接口

## 4. 明天建议按这个顺序测

1. 小程序启动
2. 定位授权
3. 首页附近诊所列表
4. 切换排序
5. 搜索诊所
6. 打开诊所详情
7. 点击电话预约
8. 点击微信预约
9. 提交一条评价
10. 进入“我的预约”
11. 进入“我的评价”

## 5. 明天重点关注的问题

优先留意这几类：

1. 微信登录是否能稳定拿到 token
2. 定位失败时首页是否能回退到北京默认坐标
3. 电话 / 微信预约动作前是否真的创建了订单
4. 标签选择数量限制是否符合规则
5. 提交评价后列表和详情是否能看到聚合变化

## 6. 如果明天测挂了，先这样排查

### 6.1 登录失败

先看：

- `WECHAT_APPID`
- `WECHAT_SECRET`
- 开发者工具里的真实 `appid`

### 6.2 列表空白

先看：

- 后端 `/api/v1/health`
- 浏览器 / 开发者工具网络面板
- 是否落到了北京种子数据范围外

### 6.3 提交评价失败

先看：

- JWT 是否存在
- 是否重复提交了同一诊所评价
- 后端日志里是否触发限流或参数校验

## 7. 明天开测前最后一眼

如果你只想记最关键的三件事，就记这三条：

1. 真实真机测试前，确认当前 `appid` 就是目标小程序的正式 `appid`
2. 先通一遍“登录 -> 列表 -> 详情 -> 预约 -> 评价 -> 我的”
3. 测脏了数据就按 [数据库备份与恢复说明](./数据库备份与恢复说明.md) 恢复
