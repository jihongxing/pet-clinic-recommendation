# 诊所数据模型 V2 定稿

## 目标

V2 将诊所信息拆为三层：

- `clinic`：基础档案，保存稳定的一手信息和展示字段。
- `capability_definition` + `clinic_capability`：能力字典与诊所能力档案，保存“会不会做、有没有配置、接不接某类宠物”这类客观能力。
- `clinic_submission`：用户提交的推荐、补充、纠错草稿，作为能力信息与基础资料的审核入口。

## 职责边界

### `clinic`

保存最终对外展示的基础信息：

- 名称、地址、电话、营业时间、坐标
- `summary`
- `cover_photo_url`
- `gallery_photos_json`
- `capability_profile_status`

不直接存每个能力项明细，能力项统一下沉到 `clinic_capability`。

### `capability_definition`

保存统一能力字典：

- `code`
- `name`
- `type`
- `sort_order`
- `is_active`

`type` 只允许：

- `service`
- `specialty`
- `equipment`
- `facility`
- `species_supported`

### `clinic_capability`

保存诊所已入库的正式能力档案：

- `clinic_id`
- `capability_id`
- `source_type`
- `verification_status`
- `confidence_score`
- `note`
- `evidence_photos_json`
- `verified_at`
- `verified_by`

约束：

- 同一诊所同一能力只保留一条正式记录，使用 `(clinic_id, capability_id)` 唯一约束。
- 后台审核通过的用户补充默认写入：
  - `source_type = user_submission`
  - `verification_status = verified`
- 后台手动维护默认写入：
  - `source_type = admin_manual`
  - `verification_status = verified`

### `clinic_submission`

保存待审核草稿，同时兼容推荐新诊所、补充信息、纠错：

- 原有基础字段继续保留
- 新增能力草稿字段：
  - `services_json`
  - `specialties_json`
  - `equipment_json`
  - `facilities_json`
  - `species_supported_json`
  - `capability_notes`

这些字段存能力 `code` 数组，不直接存展示名，便于字典统一映射。

## 状态枚举

### `clinic.capability_profile_status`

- `empty`：尚未建立能力档案
- `pending`：已有草稿或待人工补齐
- `verified`：已有正式能力档案

### `clinic_capability.source_type`

- `user_submission`
- `admin_manual`

### `clinic_capability.verification_status`

- `pending`
- `verified`
- `rejected`

## 关系说明

- 一个 `clinic` 可以关联多个 `clinic_capability`
- 一个 `capability_definition` 可以被多个 `clinic_capability` 引用
- 一个 `clinic_submission` 可以在审核通过后：
  - 新建 `clinic`
  - 或更新已有 `clinic`
  - 同步写入/更新多条 `clinic_capability`

## 写入原则

1. 用户侧提交永远先写 `clinic_submission`。
2. 审核通过后才写 `clinic` 与 `clinic_capability`。
3. 能力档案按能力 `code` 去重合并，不重复插入。
4. 详情接口同时返回：
   - 基础档案
   - 能力分组
   - 原有口碑 `tags`
