# 测试账号与种子数据说明

## 目标

这份文档对应 `T6-09`，用于把明天真机测试需要用到的“账号方式”和“现成数据范围”提前说清楚。

## 1. 当前账号机制

这个项目没有传统的“账号密码登录”。

当前支持两种方式：

### 1.1 真机 / 开发者工具真实微信登录

- 前端通过 `wx.login()` 获取 code
- 后端调用 `POST /api/v1/auth/login`
- 如果用户首次登录，后端会自动创建用户

这意味着明天真机测试时，你直接用自己的微信就能进，不需要额外准备用户名和密码。

### 1.2 开发环境 mock 登录

后端开发环境支持 `dev:<openid>` 形式的 mock 登录。

例如：

```text
dev:petmed-smoke-user-001
```

这个能力更适合本地接口联调、Swagger 验证和自动化测试，不建议拿它替代真机测试。

## 2. 当前种子数据范围

仓库已经准备了：

- 标签种子数据
- 北京地区首批诊所种子数据

你会在前端里看到几个相关兜底提示，例如：

- 开发种子数据当前仅覆盖北京，已切换到北京默认坐标

所以明天真机测时，建议：

- 打开定位权限
- 如果当前城市不在北京，优先测试搜索和列表兜底行为
- 必要时在北京坐标附近验证列表、地图和详情页

## 3. 适合明天真机测试的账号方案

最省事的方案是：

1. 使用真实微信登录
2. 用你自己的测试设备完成一轮预约和评价
3. 用同一个账号验证“我的预约”和“我的评价”

这样主链路最贴近真实场景。

## 4. 诊所侧测试说明

如果你明天还想顺手测“诊所回应”能力，后端还提供了开发令牌接口：

- `POST /api/v1/auth/dev-token`

它可以签发：

- 普通用户开发令牌
- 诊所后台开发令牌

这个接口默认只建议在开发 / staging 环境使用。

## 5. 明天建议优先验证的现成数据

优先测下面几类数据是否都能正常展示：

1. 诊所列表基础字段
2. 诊所详情里的联系方式
3. 标签聚合和分数字段
4. 我的预约
5. 我的评价

## 6. 收工前建议

如果你今晚还想再稳一点，可以先记住两件事：

1. 真机登录不需要准备账号密码
2. 如果测脏了数据，直接按 [数据库备份与恢复说明](./数据库备份与恢复说明.md) 恢复即可

## 7. 诊所收录与入驻 staging 验收数据

`R-20` 已经补了一套可重复执行的 staging 准备脚本，目标是让“推荐 -> 审核 -> 认领 -> 诊所登录 -> 提交回应”这条链路在 staging 上直接可走。

### 7.1 执行命令

先确认根目录已经准备好 `.env.staging`：

```powershell
Copy-Item .env.staging.example .env.staging
```

再执行：

```powershell
cd backend
npm run seed:staging:onboarding
```

脚本会自动：

- 创建或重置 staging 审核员账号
- 创建一个 staging 验收用户
- 创建一条待审核推荐单
- 创建一个待认领诊所和一条待审核认领申请
- 把结果 ID 和账号信息打印到终端

### 7.2 默认账号

如果 `.env.staging` 没有额外覆盖，默认会准备：

- 审核员账号：`review_admin`
- 审核员密码：`Admin123456!`
- 验收用户 openid：`staging-clinic-onboarding-user-001`
- 验收用户昵称：`Staging链路验收用户`

这些值都可以在 `.env.staging` 里通过下面几个变量覆盖：

- `STAGING_REVIEW_ADMIN_USERNAME`
- `STAGING_REVIEW_ADMIN_PASSWORD`
- `STAGING_REVIEW_ADMIN_DISPLAY_NAME`
- `STAGING_ONBOARDING_USER_OPENID`
- `STAGING_ONBOARDING_USER_NICKNAME`

### 7.3 脚本准备的样例数据

脚本默认会准备两条关键验收数据：

1. 待审核推荐单
   - 诊所名：`【Staging验收】新诊所推荐样例`
   - 目标：验证推荐审核队列、详情、审核通过新建诊所

2. 待认领诊所 + 待审核认领申请
   - 诊所名：`【Staging验收】待认领诊所样例`
   - 目标：验证认领审核、账号生成、诊所登录、诊所回应

### 7.4 推荐验收顺序

建议按下面顺序走：

1. 小程序或 Swagger 里确认推荐单已经存在
2. 打开 `https://<your-staging-domain>/admin-console/`
3. 用 `review_admin / Admin123456!` 登录
4. 在“推荐审核”里找到 `【Staging验收】新诊所推荐样例`
5. 执行“通过并新建诊所”
6. 在“认领审核”里找到 `【Staging验收】待认领诊所样例` 的认领申请
7. 执行“通过认领申请”
8. 记录后台返回的诊所账号
   - 用户名规则：`clinic_admin_<clinicId>`
   - 初始密码规则：`Clinic@<clinicId>888`
9. 调用 `POST /api/v1/clinic/login` 或后续诊所前台，用该账号登录
10. 调用 `POST /api/v1/clinics/:id/responses` 提交诊所回应

### 7.5 适用边界

这套 staging 数据主要服务于接口联调、admin-console 验收和提审前烟雾测试。

- 如果要测真实微信登录，仍然建议用真实微信账号
- 如果只是想验证后端链路，可以直接用脚本准备的数据和后台账号
- 如果数据被测脏，可以重新执行 `npm run seed:staging:onboarding` 覆盖到可验收状态
