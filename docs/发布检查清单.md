# 发布检查清单

## 目标

这份清单用于把“准备发布”这件事收口成一套可重复执行的动作，避免上线前靠记忆检查。

适用场景：

- staging 更新
- 小程序 `trial` 联调前
- 正式环境发版前

## 1. 发布前必须满足

### 代码门禁

仓库根目录至少执行：

```powershell
cd backend
npm run check:release

cd ..\frontend
npm run check
```

通过标准：

- 后端 `lint:check` 通过
- 后端单元测试通过
- 后端构建通过
- migration 可执行
- 标签 / 诊所 / 能力种子校验通过
- 前端 lint 通过

### 环境变量

staging / production 至少确认这些字段已经替换成真实值：

- `DB_PASSWORD`
- `JWT_SECRET`
- `WECHAT_APPID`
- `WECHAT_SECRET`
- `GRAFANA_ADMIN_PASSWORD`
- `DOMAIN_NAME`

生产口径下还需要保证：

- `SWAGGER_ENABLED=false`
- `JWT_SECRET` 不是默认开发值
- 数据库和 Redis 地址不是本地回环地址

### 数据安全

执行会影响库结构或种子数据的发布前，先做一次备份：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\backup-staging-db.ps1
```

## 2. 发布步骤

### Staging

```powershell
Copy-Item .env.staging.example .env.staging
docker compose --env-file .env.staging -f docker-compose.staging.yml up -d --build
```

### 本地或单机验收

```powershell
podman compose up -d postgres redis
cd backend
npm run start:dev
```

## 3. 发布后验证

至少验证以下端点：

1. 存活探针：`https://<DOMAIN_NAME>/api/v1/health/live`
2. 就绪探针：`https://<DOMAIN_NAME>/api/v1/health/ready`
3. 总览健康：`https://<DOMAIN_NAME>/api/v1/health`
4. 代理层健康：`https://<DOMAIN_NAME>/health`

推荐使用：

```powershell
curl https://<DOMAIN_NAME>/api/v1/health/live
curl https://<DOMAIN_NAME>/api/v1/health/ready
curl https://<DOMAIN_NAME>/api/v1/health
curl https://<DOMAIN_NAME>/health
```

主链路至少抽查：

1. 首页附近诊所列表
2. 搜索
3. 诊所详情
4. 登录
5. 一次评价或推荐提交流程

## 4. 出问题时先看哪里

### 发布刚完成就失败

优先检查：

1. `docker compose ... ps`
2. `docker compose ... logs -f backend nginx`
3. `https://<DOMAIN_NAME>/api/v1/health/ready`

### API 已启动但请求异常

优先检查：

1. Grafana 仪表盘里的错误率和 P95
2. backend 结构化日志里的 `requestId` / `path`
3. Nginx access / error log

### 涉及 migration 或脏数据

优先动作：

1. 先备份当前状态
2. 再按 [上线回滚方案](./上线回滚方案.md) 恢复应用或数据库

## 5. 建议的发布完成记录

每次 staging / production 发布后，至少记录：

1. 发布时间
2. 发布 commit
3. 是否执行过数据库备份
4. `check:release` 是否通过
5. 健康探针验证结果
6. 是否出现异常及处理方式
