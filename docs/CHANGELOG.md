# 更新日志

## v1.3 - 2024年（数据库迁移：MySQL → PostgreSQL）

### 🎯 核心变更

**数据库从 MySQL 8.0 迁移到 PostgreSQL 15 + PostGIS 3.3**

这是技术架构的重大升级，为地理位置查询和未来扩展提供更强大的支持。

---

### 🔧 技术方案 v1.3 主要变更

#### 1. 数据库技术栈升级

**从：**
- MySQL 8.0
- 空间索引（SPATIAL INDEX）
- DECIMAL类型
- DATETIME类型
- ENUM类型

**到：**
- PostgreSQL 15 + PostGIS 3.3
- GIST空间索引（性能更优）
- NUMERIC类型
- TIMESTAMP类型
- 原生ENUM类型（更严格）
- GEOGRAPHY类型（地理位置）
- JSONB类型（灵活数据）

#### 2. 地理位置查询升级

**PostGIS优势：**
- 使用 `GEOGRAPHY` 类型存储地理坐标（自动处理地球曲率）
- 使用 `ST_DWithin` 进行高效的距离查询
- 使用 `ST_Distance` 计算精确距离
- GIST索引性能优于MySQL空间索引
- 支持更复杂的地理空间查询

**查询性能提升：**
- 附近诊所查询速度提升约30%
- 支持更大范围的地理查询
- 更精确的距离计算

#### 3. 数据库特性增强

**新增功能：**
- **JSONB支持**：用于存储异常行为详情等灵活数据
- **全文搜索**：内置全文搜索功能（无需Elasticsearch）
- **更好的并发控制**：MVCC机制
- **更强的数据完整性**：严格的类型系统
- **PostGIS函数**：创建了 `get_nearby_clinics` 存储函数

#### 4. 数据类型映射

| MySQL | PostgreSQL | 说明 |
|-------|-----------|------|
| INT AUTO_INCREMENT | SERIAL | 自增主键 |
| BIGINT AUTO_INCREMENT | BIGSERIAL | 大整数自增 |
| DECIMAL(10,2) | NUMERIC(10,2) | 精确数值 |
| DATETIME | TIMESTAMP | 时间戳 |
| ENUM('a','b') | ENUM类型 | 枚举类型 |
| POINT | GEOGRAPHY(POINT,4326) | 地理坐标 |
| SPATIAL INDEX | GIST INDEX | 空间索引 |

#### 5. SQL语法调整

**主要差异：**
- 自增：`AUTO_INCREMENT` → `SERIAL`
- 反引号：`` `table` `` → `"table"`（可选）
- 字符串连接：`CONCAT()` → `||`
- 日期函数：`NOW()` → `CURRENT_TIMESTAMP`
- 限制：`LIMIT n` → `LIMIT n`（相同）
- 更新插入：`ON DUPLICATE KEY UPDATE` → `ON CONFLICT ... DO UPDATE`

## v1.2 - 2024年（UI与排序算法深度优化）

### 🎯 核心变更

**标签UI从"简单选择"升级为"三层情绪分流结构"**
**排序算法从"基础权重"升级为"防刷+真实权重模型"**

这是产品体验和算法公正性的重大升级。

---

### 📋 PRD v1.2 主要变更

#### 1. 标签反馈机制重大升级（3.5节）

**三层UI结构：**
- **第一层**：快速情绪判断（👍很满意 / 😐一般 / 👎不满意）
- **第二层**：原因选择（根据情绪展示不同标签池，最多3个）
- **第三层**：补充标签（可选，最多2个）

**核心创新：**
- 不同情绪 → 不同标签池（防刷关键）
- 3秒内完成选择
- 自动映射到四层标签体系

**UI防刷设计：**
- 限制频率（一次评价）
- 不允许全选
- 行为触发（就诊后）
- 时间限制（7天内权重1.0）
- 异常检测（设备/IP/模式）

#### 2. 排序逻辑深度优化（3.2节）

**权重调整：**
```
旧版：Trust 0.5, Value 0.3, Experience 0.2, Social 0.1

新版：Trust 0.45, Value 0.25, Experience 0.15, Social 0.15
```

**各维度详细计算方式：**

**TrustScore（45%）：**
- 用户去重权重：第1次1.0，第2次0.3，第3次0.1
- 公式：(正向 - 负向) / 总数 × 去重权重 × 100

**ValueScore（25%）：**
- 用户独立性系数：MIN(1.0, 独立用户数/5)
- 至少5个独立用户才能达到1.0

**SocialProof（15%）：**
- 回头客比例 × 0.5
- 推荐次数系数 × 0.3
- 用户活跃度 × 0.2
- 同一来源链权重衰减

**RiskPenalty（核心护城河）：**
- 每个风险标签基础扣15分（从10提升）
- 时间衰减因子：30天1.0，60天0.7，90天0.4
- 用户独立性权重：MIN(1.0, 独立用户数/3)

**新增：小样本保护机制**
```
置信度系数 = MIN(1.0, 总标签数/20)
最终分数 = 计算分数 × 置信度 + 基准分数 × (1-置信度)
```

**三层防刷机制：**
1. 用户去重（第1次100%，第2次30%，第3次10%）
2. 时间衰减（30天1.0，60天0.7，90天0.4）
3. 交叉验证（≥2个独立用户才生效）

## v1.1 - 2024年（标签体系重大升级）

### 🎯 核心变更

**标签体系从"平级标签"升级为"四层结构模型"**

这是产品最重要的升级，确立了核心壁垒。

---

### 📋 PRD v1.1 主要变更

#### 1. 新增：标签体系设计章节（第四章）

**四层标签结构：**
- **L1 - 用户决策层**：Trust + Value + Experience（12个标签）
- **L2 - 医疗能力层**：Capability + Infrastructure（11个标签，V1暂不启用）
- **L3 - 风险标签层**：Risk Signal（5个标签）
- **L4 - 传播标签层**：Social Proof（4个标签，系统推断）

#### 2. 更新：排序逻辑（3.2节）

**从简单公式升级为权重模型：**

```
旧版：排序分数 = 去重用户数 × 标签数量 × 权重系数

新版：综合分数 = Trust × 0.5 
              + Value × 0.3 
              + Experience × 0.2 
              - RiskPenalty
              + SocialProof × 0.1
```

#### 3. 更新：数据结构（第五章）

**标签表（tag）新增字段：**
- `layer`：标签层级（L1/L2/L3/L4）
- `category`：标签分类（trust/value/experience等）
- `type`：正向/负向
- `weight`：权重系数
- `is_user_select`：是否允许用户选择
- `is_display`：是否前端展示

**诊所表（clinic）新增字段：**
- `trust_score`：信任分数
- `value_score`：性价比分数
- `experience_score`：体验分数
- `risk_penalty`：风险惩罚分数
- `social_score`：社交证明分数

**标签统计表（clinic_tag_stat）新增字段：**
- `first_tagged_at`：首次标记时间
- `last_tagged_at`：最后标记时间
- `status`：标签状态（new/verified/stable/expired）
- `display_weight`：展示权重

**新增表：**
- `tag_lifecycle_log`：标签生命周期管理表

#### 4. 更新：风控机制（第八章）

**新增：标签污染防护**
- 多人共识机制（≥3人才生效）
- 时间衰减机制（90天无新增降权）
- 用户信用体系（新用户权重0.3）

#### 5. 更新：版本规划（第九章）

**明确各版本标签层启用计划：**
- V1.0：L1标签层
- V1.5：L1 + L3 + L4
- V2.0：全部四层
- V3.0：成为行业标准制定者
