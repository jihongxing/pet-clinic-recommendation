# 标签体系设计说明 v2.0 — 宠物诊所可信度模型

> **核心理念**：把"宠物诊所好不好"从主观评价，变成结构化信用模型

---

## 一、为什么标签体系是核心壁垒？

这个产品真正的壁垒不在功能，而在：

**"什么算好诊所"这件事的定义权（标签体系）**

如果标签体系设计错，后面所有扩展（推荐、排序、商业化）都会失真。

---

## 二、设计目标

标签体系必须同时满足：

| 目标 | 说明 | 为什么重要 |
|-----|------|-----------|
| **可理解** | 用户视角：能快速判断好/不好/贵不贵 | 降低决策成本 |
| **可计算** | 系统视角：能参与排序，而不是装饰 | 算法基础 |
| **抗污染** | 不允许自由发散 | 防刷核心 |
| **可扩展** | 能支撑"专业能力地图" | 未来壁垒 |

---

## 三、四层标签结构（核心升级）

v2 不再是"平级标签"，而是：**四层结构标签体系**

```
L1: 用户决策层 (User Decision)
    ↓ 直接展示给用户
    
L2: 医疗能力层 (Medical Capability)
    ↓ 用于精准推荐
    
L3: 风险标签层 (Risk Signal)
    ↓ 用于降权和风控
    
L4: 传播标签层 (Social Proof)
    ↓ 用于冷启动和增长
```

---

### 🧩 L1：用户决策层（最重要）

**作用**：首页展示的核心标签，用户做决策用

#### ① 信任类（Trust）- 代表"不会坑你"
- 不乱开药
- 不过度检查
- 解释清楚病情
- 没有隐性收费

#### ② 性价比类（Value）- 代表"值不值"
- 价格透明
- 基础诊疗便宜
- 不强推高价项目
- 检查合理收费

#### ③ 服务体验类（Experience）- 代表"体验好不好"
- 医生态度好
- 对宠物耐心
- 环境干净
- 响应快

**权重配置：**
- Trust: 50%（最高权重，宠物医疗是强信任行业）
- Value: 30%
- Experience: 20%

---

### 🧠 L2：医疗能力层（未来壁垒）

**作用**：不直接展示，用于排序和推荐算法

#### ④ 专科能力（Capability）
- 猫专科
- 狗外科
- 皮肤病专长
- 骨科能力
- 急诊能力
- 传染病处理

#### ⑤ 设备能力（Infrastructure）
- 有DR/X光
- 有B超
- 可做手术
- 可住院
- 有化验室

**应用场景：**
- "附近哪家能做猫绝育？"
- "哪家有骨科能力？"
- "急诊去哪里？"

**V1暂不开放**，V2版本启用

---

### 🚨 L3：风险标签层（核心护城河）

**作用**：行业没人敢做，但这是"信任系统"的核心

#### ⑥ 风险信号（Negative Trust）
- 有价格争议记录
- 有过医疗纠纷
- 过度推荐手术嫌疑
- 用户投诉较多
- 多次更换医生

**展示规则：**
- ❗不在首页显眼位置展示
- 仅在详情页底部灰色区域提示
- 主要用于：降权、风控、排序修正

**触发机制：**
- 用户主动标记（需审核，≥3人自动通过）
- 系统行为推断（如：退款率高）
- 多人投诉（≥3人）

**权重影响：**
- 每个风险标签 -10分

---

### 📢 L4：传播标签层（轻权重）

**作用**：用于冷启动和增长

#### ⑦ 社交传播类
- 被推荐次数高
- 回头客多
- 熟人推荐率高
- 本地口碑好

**生成方式：**
- 系统行为推断（如：同一用户多次预约 → "回头客多"）
- 用户邀请数据统计
- 社交分享次数

**权重配置：**
- Social: 10%（加分项）

---

## 四、标签生成机制（决定能否活下来）

> **核心原则**：把"随意评论"变成"结构化判断选择"

### 4.1 核心原则

**✅ 允许：**
- 用户从预设标签中选择
- 系统根据行为推导
- 场景化问题引导

**❌ 禁止：**
- 自由文本评论
- AI从评论中抽取标签（V1不做）
- 多层筛选复杂UI

---

### 4.2 标签UI设计（三层结构）

#### 触发时机
- 用户点击"已就诊"按钮
- 预约后24小时推送提醒

#### 第一层：快速情绪判断（必选1个）

**标题**："这次就诊体验怎么样？"

**交互**：用按钮，不用标签

```
┌─────────────────────────────────┐
│  👍 很满意   😐 一般   👎 不满意  │
└─────────────────────────────────┘
```

**目的**：
- 快速分流
- 不同情绪进入不同标签池
- 防止刷标签（情绪不同，标签池不同）

---

#### 第二层：原因选择（最多选3个）

**根据第一层选择，展示不同标签池：**

**如果选择 👍 很满意：**
- 医生很专业 → L1-Trust: 不乱开药
- 价格合理 → L1-Value: 价格透明
- 解释清楚 → L1-Trust: 解释清楚病情
- 不乱推荐检查 → L1-Trust: 不过度检查
- 对宠物很耐心 → L1-Experience: 对宠物耐心
- 环境干净 → L1-Experience: 环境干净

**如果选择 😐 一般：**
- 价格略高 → L1-Value: 基础诊疗便宜（负向0.5权重）
- 等待时间长 → L1-Experience: 响应快（负向0.5权重）
- 沟通一般 → L1-Trust: 解释清楚病情（负向0.5权重）
- 检查项目多 → L1-Trust: 不过度检查（负向0.5权重）
- 环境一般 → L1-Experience: 环境干净（负向0.5权重）

**如果选择 👎 不满意：**
- 乱收费 → L3-Risk: 有价格争议记录
- 过度检查 → L3-Risk: 过度推荐手术嫌疑
- 不专业 → L3-Risk: 有过医疗纠纷
- 体验差 → L1-Experience: 医生态度好（负向）
- 态度不好 → L1-Experience: 医生态度好（负向）
- 强推高价项目 → L3-Risk: 有价格争议记录

**核心设计点：**
- ❗不同情绪 → 不同标签池（防刷关键）
- 最多选3个，至少选1个
- 自动映射到四层标签体系

---

#### 第三层：补充标签（可选，最多选2个）

**轻标签（不影响排序，仅供参考）：**
- 猫更友好
- 狗更友好
- 急诊不错
- 有停车位
- 交通方便
- 可以洗澡

**说明**：
- 这一层可跳过
- 最多选2个
- 权重较低（0.3）

---

### 4.3 UI防刷设计（很重要）

#### 1️⃣ 限制频率
- 同一用户同一诊所：**只能一次评价**
- 数据库唯一索引强制约束

#### 2️⃣ 不允许"全选"
- 第一层：必选1个
- 第二层：最多3个，至少1个
- 第三层：最多2个，可跳过

#### 3️⃣ 行为触发而不是主动评论
- 只能在"就诊后流程"出现
- 未预约用户不能直接打标签（或权重极低0.3）

#### 4️⃣ 时间限制
- 预约后7天内有效（权重1.0）
- 7-30天内（权重0.7）
- 超过30天不再提醒

#### 5️⃣ 异常检测
- 同一设备短时间内多次评价 → 降权
- 评价模式高度相似 → 人工审核
- IP地址异常 → 标记

---

### 4.4 标签来源三条路径

#### ① 用户行为（主来源）
- 就诊后选择标签（最多3个）
- 权重：
  - 预约后7天内打标签 = 1.0
  - 预约后7-30天打标签 = 0.7
  - 普通打标签（未预约） = 0.5
  - 新用户（7天内）打标签 = 0.3

#### ② 多人共识（加权）
- ≥2人选择同一标签 → 标签生效
- <2人 → 标签存在但不展示
- ≥10人 + 30天稳定 → 标签权重1.2

#### ③ 行为推断（系统）
- 频繁复购 → "回头客多"（L4）
- 价格集中在低区间 → "性价比高"（L4）
- 退款率高 → 触发风险标签（L3）
- 投诉记录 → 触发风险标签（L3）

---

### 4.5 目的总结

> **把"评论系统"变成"结构化反馈系统"**

**不是让用户表达更多，而是：**
- 让用户在3秒内做出可信选择
- 通过情绪分流防止刷标签
- 通过限制数量提高质量
- 通过行为触发保证真实性

## 五、标签权重体系（用于排序）

> **核心问题**：怎么让真实好诊所排前面，而不是会运营的诊所排前面

### 5.1 综合分数公式（V2升级版）

```
综合分数 = TrustScore × 0.45 
         + ValueScore × 0.25 
         + ExperienceScore × 0.15 
         + SocialProof × 0.15 
         - RiskPenalty
```

**权重调整说明：**
- Trust从0.5降至0.45（防止单一维度操控）
- Social从0.1提升至0.15（强调长期一致性）
- 总权重100%，风险惩罚额外扣除

---

### 5.2 各维度详细计算

#### 🟢 TrustScore（信任分）- 权重45%

**计算公式：**
```
TrustScore = (正向标签数 - 负向标签数) / 总标签数 × 用户去重权重 × 100
```

**用户去重权重（防刷核心）：**
- 第1次评价 = 1.0
- 第2次评价 = 0.3
- 第3次及以上 = 0.1

---

#### 🟡 ValueScore（性价比分）- 权重25%

**计算公式：**
```
ValueScore = 性价比标签加权数 / 总标签数 × 用户独立性系数 × 100
```

**用户独立性系数：**
```
独立性系数 = MIN(1.0, 独立用户数 / 5)
```

**说明：**至少需要5个独立用户，系数才能达到1.0

---

#### 🔵 ExperienceScore（体验分）- 权重15%

**计算公式：**
```
ExperienceScore = 体验标签加权数 / 总标签数 × 100
```

**权重最低原因：**防止主观因素过度影响

---

#### 🟣 SocialProof（社交证明）- 权重15%

**计算公式：**
```
SocialProof = (回头客比例 × 0.5 + 推荐次数系数 × 0.3 + 用户活跃度 × 0.2) × 100
```

**防刷核心：同一来源链权重衰减**
- 第1个推荐权重 = 1.0
- 第2个推荐权重 = 0.5
- 第3个及以上 = 0.2

---

#### 🔴 RiskPenalty（风险惩罚）- 核心护城河

**计算公式：**
```
RiskPenalty = Σ(负面标签权重 × 时间衰减因子 × 用户独立性权重)
```

**时间衰减因子：**
- 30天内 = 1.0
- 31-60天 = 0.7
- 61-90天 = 0.4
- 90天以上 = 0.2

**惩罚力度：**
- 每个风险标签基础扣分 = 15分
- 实际扣分 = 15 × 时间衰减因子 × 独立性权重

---

### 5.3 防刷机制（三层防护）

#### 1️⃣ 用户去重（第一层）
- 第1次评价权重 = 100%
- 第2次评价权重 = 30%
- 第3次评价权重 = 10%

#### 2️⃣ 时间衰减（第二层）
- 最近30天 = 1.0
- 31-60天 = 0.7
- 61-90天 = 0.4
- 90天以上 = 0.2

#### 3️⃣ 交叉验证（第三层）
- 只有 ≥2个独立用户 给出相同标签
- 标签才进入"有效状态"

---

### 5.4 小样本保护机制

**置信度系数：**
```
置信度系数 = MIN(1.0, 总标签数 / 20)

最终分数 = 计算分数 × 置信度系数 + 基准分数 × (1 - 置信度系数)
```

**基准分数：**城市平均分 = 60分

**目的：**
- 新诊所向平均分回归
- 需要积累足够标签才能排名靠前
- 防止刷分快速上位

---

### 5.5 口碑优先排序

```
排序分数 = TrustScore × 0.55 
         + ValueScore × 0.20 
         + ExperienceScore × 0.15 
         + SocialProof × 0.10 
         - RiskPenalty
```
排序分数 = Trust × 0.6 
         + Value × 0.2 
         + Experience × 0.2 
         + Social × 0.1 
         - Risk
```

### 5.3 性价比优先排序

```
排序分数 = Value × 0.5 
         + Trust × 0.3 
         + Experience × 0.2 
         + Social × 0.1 
         - Risk
```

## 六、标签生命周期（防污染核心）

每个标签有生命周期状态：

| 状态 | 条件 | 权重 | 是否展示 | 作用 |
|-----|------|------|---------|------|
| **新标签** | <3人标记 | 0.3 | 否 | 防止刷标签 |
| **验证标签** | ≥3人标记 | 1.0 | 是 | 正常展示 |
| **稳定标签** | ≥10人 + 30天稳定 | 1.2 | 是（加粗） | 权重提升 |
| **失效标签** | 90天无新增 | 0.5 | 是（灰色） | 时间衰减 |

**目的**：防止"短期刷标签影响长期排序"

## 八、这个体系的真正护城河

不是标签本身，而是：

### 1. 标签的生成权
**什么算好诊所，我们定义**

- 不是大众点评的"好评/差评"
- 不是美团的"星级评分"
- 而是结构化的信用模型

### 2. 标签的解释权
**标签背后的权重模型**

- Trust为什么是50%？
- 为什么风险标签-10分？
- 为什么新标签权重0.3？

这些规则的制定权和调整权，就是壁垒。

### 3. 标签的演化能力
**从用户决策到行业地图**

- L1 → 用户能用
- L2 → 精准推荐
- L3 → 风险控制
- L4 → 增长引擎

四层标签的组合，形成完整的信用体系。

| **演化能力** | 弱 | 弱 | 强（四层） |

## 十一、关键成功因素

### 1. 冷启动数据质量
- 初始50-100家诊所
