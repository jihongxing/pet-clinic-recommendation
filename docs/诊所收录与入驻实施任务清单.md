# 诊所收录与入驻实施任务清单

> 来源：基于 [诊所收录与入驻双链路设计稿](./诊所收录与入驻双链路设计稿.md) 拆解
> 目标：把“推荐诊所、后台审核、诊所认领”拆成可排期、可验收的任务

---

## 1. 任务范围

### 1.1 用户推荐链路

- 用户可以提交“推荐新诊所 / 补充已有诊所 / 纠错”。
- 用户可以查看自己的推荐状态。

### 1.2 审核后台链路

- 审核员可以看推荐队列。
- 审核员可以通过、合并、驳回、要求补充。
- 审核员可以查看审核日志。

### 1.3 诊所认领链路

- 诊所可以申请认领已有诊所。
- 审核员可以通过或驳回认领。
- 通过后生成或启用诊所后台账号。

---

## 2. 数据层任务

- [x] `R-01` 新增 `clinic_submission` 表和 Entity
  - 优先级：P0
  - 依赖：无
  - 验收标准：用户推荐/纠错记录可落库，支持 `pending_review / need_info / approved_new / merged / rejected`

- [x] `R-02` 新增 `clinic_submission_review_log` 表和 Entity
  - 优先级：P0
  - 依赖：`R-01`
  - 验收标准：每次审核动作都有独立留痕

- [x] `R-03` 补齐推荐状态枚举和 DTO
  - 优先级：P0
  - 依赖：`R-01`
  - 验收标准：接口与前端状态枚举一致

- [x] `R-04` 复核 `clinic_claim_request` 字段是否满足审核页展示
  - 优先级：P1
  - 依赖：现有迁移
  - 验收标准：认领审核页不需要临时拼字段

---

## 3. 用户推荐链路任务

- [x] `R-05` 新增推荐入口
  - 优先级：P0
  - 依赖：`R-01`
  - 范围：首页空态、搜索无结果、详情页、我的页
  - 验收标准：用户能从任一入口进入推荐页

- [x] `R-06` 新增推荐页 `pages/recommend-clinic/recommend-clinic`
  - 优先级：P0
  - 依赖：`R-05`
  - 验收标准：可提交新诊所、补充信息、纠错三种表单

- [x] `R-07` 新增“我的推荐”页 `pages/my-submissions/my-submissions`
  - 优先级：P0
  - 依赖：`R-01`、`R-03`
  - 验收标准：用户可查看推荐记录和状态流转

- [x] `R-08` 增加推荐提交前的候选诊所匹配展示
  - 优先级：P1
  - 依赖：`R-01`
  - 验收标准：用户提交前能看到可能重复的候选诊所

---

## 4. 后台审核任务

- [x] `R-09` 新增后台审核登录/鉴权方案
  - 优先级：P0
  - 依赖：无
  - 验收标准：审核员和普通用户权限隔离

- [x] `R-10` 新增推荐审核列表页
  - 优先级：P0
  - 依赖：`R-01`、`R-02`
  - 验收标准：可按状态、城市、时间筛选推荐单

- [x] `R-11` 新增推荐审核详情页
  - 优先级：P0
  - 依赖：`R-10`
  - 验收标准：可查看推荐内容、候选重复、审核备注

- [x] `R-12` 实现推荐审核动作
  - 优先级：P0
  - 依赖：`R-02`
  - 验收标准：通过 / 合并 / 驳回 / 补充信息四种动作都能落库

- [x] `R-13` 新增审核日志页
  - 优先级：P1
  - 依赖：`R-02`
  - 验收标准：能追踪每个审核动作的操作人和备注

## 5. 诊所认领任务

- [x] `R-14` 新增诊所认领入口和申请页
  - 优先级：P0
  - 依赖：现有 `clinic_claim_request`
  - 验收标准：诊所可提交认领申请

- [x] `R-15` 新增认领状态页
  - 优先级：P1
  - 依赖：`R-14`
  - 验收标准：诊所可查看申请状态、审核备注、结果

- [x] `R-16` 新增认领审核页
  - 优先级：P0
  - 依赖：`R-14`
  - 验收标准：审核员可通过或驳回认领申请

- [x] `R-17` 认领通过后创建或启用 `clinic_account`
  - 优先级：P0
  - 依赖：`R-16`
  - 验收标准：认领成功后诊所可登录后台并提交回应

## 6. 联调与验收任务

- [x] `R-18` 补齐推荐和认领相关单元测试
  - 优先级：P0
  - 依赖：`R-01` 到 `R-17`
  - 验收标准：核心状态流转有测试覆盖

- [x] `R-19` 补齐端到端测试
  - 优先级：P0
  - 依赖：`R-06`、`R-10`、`R-14`
  - 验收标准：推荐 -> 审核 -> 认领主链路可跑通

- [x] `R-20` 准备 staging 测试数据和审核账号
  - 优先级：P1
  - 依赖：`R-09`
  - 验收标准：可直接用 staging 走通完整流程

- [x] `R-21` 确定推荐图片存储方案
  - 优先级：P1
  - 依赖：`R-06`
  - 验收标准：推荐页能稳定保存图片，且后端有统一存储字段或上传入口

---

## 7. 推荐实施顺序

1. 先做 `R-01` 到 `R-04`，把数据模型定住。
2. 再做 `R-05` 到 `R-08`，把用户推荐链路跑通。
3. 再做 `R-09` 到 `R-13`，把审核后台补齐。
4. 最后做 `R-14` 到 `R-20`，把诊所认领和联调收口。
